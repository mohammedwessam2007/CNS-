# AXIS FORGE v0 · Cognitive Organogenesis Observer

**Parent:** INTELLECTUALITY / Renaissance v18.4  
**Branch:** `astra/axis-forge-v0`  
**Role:** successor research organ, not a replacement for Renaissance  
**Status:** implemented; CI and preview deployment decide whether it is promotable

## 1. Mission

Axis Forge asks a narrower and harder question than Renaissance:

> Are repeated combinations of known capabilities beginning to behave like a distinct transferable faculty?

It does **not** call a capability new because it has a dramatic name. It observes evidence already generated by Renaissance and by explicit real-world reports, rejects renamed atoms and known compounds, and only allows a candidate to advance when the same combination works unaided across multiple domains.

The target is **cognitive organogenesis**: discovering useful, reproducible human faculties that are not adequately described by the current capability atoms.

## 2. Constitutional boundary

Axis Forge v0 is deliberately observational.

It does not:

- change the Renaissance curriculum;
- generate lessons;
- call a model or network service;
- alter CNS state;
- spend money;
- promote a faculty automatically;
- claim psychometric IQ change, AGI resistance, or biological neural change;
- treat AI-assisted performance as unaided human capability.

It stores its own state under `axis_forge_v1`.

Kill switches:

- `localStorage.axis_forge_off = "1"`
- `?axisforge=off`

## 3. Evidence pipeline

A candidate moves through:

`OBSERVED → CANDIDATE → PROBE → REPLICATED → TRANSFERRED → PROMOTED`

and may become `REVOKED` at any time.

A candidate cannot reach `TRANSFERRED` unless it has at least:

- 15 observations;
- 3 domains with unaided successes;
- 8 unaided human successes;
- 2 held-out successes;
- 2 real-world unaided successes;
- 70% overall success.

Those floors are intentionally conservative first defaults, not scientific constants. Longitudinal evidence may revise them, but changes must preserve the no-self-promotion law.

`PROMOTED` requires the literal explicit approval token `HUMAN_APPROVED`. This is a machine guard, not a claim that a string is sufficient governance for consequential external action. No external action exists in v0.

## 4. Anti-fantasy / anti-renaming law

A proposed faculty fails novelty immediately when:

1. it is only one registered Renaissance atom; or
2. its exact atom set is already a registered Renaissance compound.

Any other combination is labelled only `COMPOUND_CANDIDATE`.

That label means:

> "not already in the current registry"

not:

> "new to science" or "never existed in another human."

True novelty would require prior-art work and stronger evidence later.

## 5. What is observed

On load, after Renaissance is available, Axis Forge scans `RENAISSANCE.state().answers`.

An answer contributes:

- its capability atoms;
- the domain of the session;
- correctness;
- whether it was transfer-like / delayed / sealed;
- whether it was hinted.

Only transfer-like, unhinted success counts as unaided evidence.

The observer is idempotent: a Renaissance answer is ingested once by a stable evidence id.

Explicit external observations can also be recorded through:

`AXIS_FORGE.observe({...})`

This is the future bridge for medicine, UberBond, MMA, acting, research, social life, creation, or other real environments. v0 does not infer those events by surveillance.

## 6. New Axis Test, v0

A candidate is interesting only when it begins to satisfy all of the following:

1. **Not a renamed old skill.**
2. **Repeated:** succeeds more than once.
3. **Unaided:** survives without AI/hints.
4. **Cross-domain:** works in genuinely different domains.
5. **Held-out:** works on tasks not used to train it.
6. **Real:** survives at least two real-world uses.
7. **Reversible:** can be revoked if later evidence collapses.
8. **Sovereign:** no automatic promotion.

Later versions should add:

- matched baseline tasks;
- explicit counterfactual "without this organ" probes;
- prior-art search;
- human examiner evidence;
- longitudinal decay / retention;
- an independence test from the source atoms.

## 7. Probe compiler

`AXIS_FORGE.probe(id)` returns a next-test prescription rather than another lesson.

The next probe prefers an unseen domain and requires:

- a task not used for training;
- commitment before feedback;
- no AI, hints, notes, or answer key during the attempt;
- success/failure plus confidence recorded;
- a real consequence or held-out task when possible.

The probe is designed to **kill** weak hypotheses quickly.

## 8. Future-AI Obsolescence Filter

`AXIS_FORGE.aiFilter(spec)` implements the Post-AGI Renaissance allocation rule discussed after v18.4.

It does not predict when AGI arrives.

It scores a task/capability on two broad axes:

### Machine pressure

How much the task is:

- digital;
- clearly specified;
- easily verified;
- repeatable;
- data-rich.

### Human internalisation value

How much it depends on or develops:

- embodiment;
- judgment;
- culture;
- sovereignty;
- mind transformation;
- creation.

It outputs one of:

- `OUTSOURCE`
- `INTERNALIZE`
- `EXPERIENCE`
- `EMBODY`
- `COEVOLVE`

The intended rule is not "learn what current AI cannot do." It is:

> Spend biological learning time on capabilities that remain valuable under much stronger future AI, and outsource the rest while preserving enough internal mastery to judge and direct machines.

## 10. Runtime integration

The canonical Renaissance source remains untouched.

Vercel's build step injects:

```html
<script defer src="/axis-forge-v1.js"></script>
```

immediately after `renaissance-v1.js`.

This means v18.4 remains the stable parent organism while Axis Forge can be killed or rolled back independently.

## 11. Verification

`tests/axis_forge_test.js` attacks:

- storage isolation;
- fake novelty;
- known-compound renaming;
- duplicate evidence;
- unaided evidence accounting;
- cross-domain stage gates;
- human approval;
- AI-assistance contamination;
- future-AI allocation;
- probe independence;
- revocation;
- corrupt-state recovery;
- kill switch;
- export/import.

The GitHub workflow additionally performs a Vercel build with picture downloads disabled and fails unless the built page contains Axis Forge and the asset exists.

## 12. What "complete" means here

v0 is complete when:

1. its unit/hostile checks pass;
2. the Vercel build contains the observer;
3. the branch preview is healthy;
4. production v18.4 is unchanged;
5. no candidate is falsely promoted before real evidence exists.

That does **not** mean Axis Forge has discovered a new cognitive faculty. The first such claim can only be earned by future human evidence.

## 13. Next frontier after v0

Once enough evidence exists, the highest-value successor is not a bigger ontology document. It is a **probe foundry**:

observed unexplained performance  
→ candidate faculty  
→ independent task generator  
→ no-AI transfer trial  
→ real-world trial  
→ prior-art comparison  
→ promote / merge / kill.

That is where "Axis Forge" becomes an empirical program rather than a name.
