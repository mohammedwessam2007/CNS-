# Opus Research + Brainstorm Tournament

Opus is not only a coder. It operates as five roles simultaneously:

1. **Learning scientist**
2. **Medical visual curator**
3. **Personal tutor architect**
4. **Software / performance engineer**
5. **Adversarial verifier**

## Phase A: recover truth
Before ideas:
- inspect exact v53 source
- run current app
- trace real learner paths
- identify current defects from behavior, not from filenames

## Phase B: current research
Research 2026 state of the art in:
- medical-school visual learning
- neuroanatomy atlases
- histology virtual microscopy
- adaptive tutoring
- retrieval / spacing / interleaving
- worked-example fading
- error-driven learning
- misconception diagnosis
- cognitive load
- multimedia learning
- confidence calibration
- mastery modeling
- time-aware scheduling
- exam simulation
- accessible iPad-first course UI

Separate:
- replicated learning-science evidence
- plausible product heuristics
- marketing claims

Do not cargo-cult trendy AI features.

## Phase C: capability brainstorm
Generate a broad internal candidate set. At minimum brainstorm across:
- visual specificity
- visual diversity
- wrong-answer explanation
- question-independent conceptual teaching
- multimodal animations
- practical recognition
- personal tutor language
- Egyptian-Arabic memory triggers
- source provenance
- calendar recovery
- focus / fatigue adaptation
- accessibility
- performance
- longitudinal personalization
- cross-module portability
- teacher / resource effectiveness learning
- assessment integrity

Do not expose this as UI by default.

## Phase D: tournament
Score each candidate on:
- expected increase in understanding
- expected exam-mark gain
- minutes saved
- long-term retention value
- personalization value
- evidence quality
- implementation risk
- assessment-leak risk
- medical-error risk
- UI complexity cost
- runtime/network cost
- maintenance cost

The north-star score is approximately:

`(expected reliable marks + understanding + retention + transferable mental models + free minutes returned) / (cognitive minutes + UI friction + risk)`

Reject capabilities that are impressive demos but worsen this score.

## Phase E: implement only the winners
The ideal visible surface is still:

`Resume learning`

Complexity belongs underneath.

## Phase F: adversarial certification
Attack every newly introduced behavior with:
- fresh user
- legacy user
- wrong answer
- confident wrong
- repeated visual
- broken remote visual
- no licensed distractor image
- midnight rollover
- missed day
- held-out mock
- low-bandwidth mobile
- iPad portrait
- stale cloud state
- offline / timeout fallback where relevant

Do not call a capability finished because one happy-path screenshot looks good.
